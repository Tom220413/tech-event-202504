# Claude Code指示テンプレート

## 基本テンプレート

### 新機能実装時
```
## タスク概要
[機能名]の実装

## 要件
- [具体的な要件1]
- [具体的な要件2]
- [具体的な要件3]

## テスト要件（TDD）
- [ ] ユニットテストの作成
- [ ] 統合テストの作成
- [ ] エラーケースのテスト
- [ ] エッジケースのテスト

## 技術的制約
- Next.js 15.1.8
- Supabase認証
- 既存のAPIエンドポイントとの整合性
- レスポンシブデザイン対応

## 期待結果
- [具体的な動作1]
- [具体的な動作2]
- [パフォーマンス要件]

## 実装順序
1. テスト作成（Red）
2. 最小限の実装（Green）
3. リファクタリング（Refactor）
4. ドキュメント更新
```

### バグ修正時
```
## タスク概要
[バグの概要]の修正

## 問題の詳細
- [バグの現象]
- [再現手順]
- [期待される動作]

## テスト要件
- [ ] 再現テストの作成
- [ ] 修正後の動作確認テスト
- [ ] 関連機能への影響確認

## 技術的制約
- 既存テストを壊さない
- パフォーマンスへの影響を最小限に
- セキュリティ問題がないことを確認

## 期待結果
- バグが修正される
- 既存機能に影響がない
- テストカバレッジが維持される
```

## 具体的な指示例

### 例1: バリデーション関数の実装
```
## タスク概要
課題フォームのバリデーション関数の実装

## 要件
- タイトル: 必須、30文字以内
- 内容: 必須、225文字以内
- 優先度: 必須、'高'|'中'|'低'
- タグ: 必須、'開発'|'デザイン'|'ドキュメント'|'インフラ'|'その他'
- 期限: 必須、YYYY-MM-DD形式
- 担当者名: 必須、32文字以内

## テスト要件
- [ ] 正常なデータの検証
- [ ] 各フィールドの必須チェック
- [ ] 文字数制限の検証
- [ ] 不正な値の検証
- [ ] エラーメッセージの確認

## 技術的制約
- 既存のフォームバリデーションロジックとの整合性
- 国際化対応（将来的）

## 期待結果
- バリデーション関数が100%テストカバー
- エラーメッセージが適切に表示される
- 既存のフォームが正常に動作する

## 実装順序
1. バリデーション関数のテスト作成
2. バリデーション関数の実装
3. 既存フォームへの統合
4. 動作確認
```

### 例2: APIエンドポイントのテスト
```
## タスク概要
課題作成API（POST /api/register）の統合テスト実装

## 要件
- 正常な課題作成のテスト
- バリデーションエラーのテスト
- 認証エラーのテスト
- レスポンス形式の確認

## テスト要件
- [ ] 正常なデータでの課題作成
- [ ] 必須フィールド不足のエラー
- [ ] 文字数制限超過のエラー
- [ ] 不正な優先度・タグのエラー
- [ ] 認証なしでのアクセスエラー
- [ ] レスポンスステータスコードの確認

## 技術的制約
- MSWを使用したモック
- Supabase認証のモック化
- 既存のAPIエンドポイントとの整合性

## 期待結果
- 全テストケースが通る
- エラーハンドリングが適切に動作する
- セキュリティが確保される

## 実装順序
1. テストケースの作成
2. MSWハンドラーの実装
3. テストの実行・確認
4. エラーケースの追加
```

## 注意事項

### Claude Code使用時のチェックリスト
- [ ] 要件が明確に定義されているか
- [ ] テスト要件が含まれているか
- [ ] 技術的制約が明記されているか
- [ ] 期待結果が具体的か
- [ ] 実装順序が適切か

### レビュー時のチェックリスト
- [ ] 生成されたコードが要件を満たしているか
- [ ] テストが適切に作成されているか
- [ ] 既存コードとの整合性があるか
- [ ] セキュリティ問題がないか
- [ ] パフォーマンス問題がないか
- [ ] ドキュメントが更新されているか

### よくある問題と対策
1. **要件が曖昧**: 具体的な数値や条件を明記
2. **テスト不足**: エラーケースも含めてテスト要件を明記
3. **既存コードとの不整合**: 技術的制約を詳細に記載
4. **セキュリティ考慮不足**: セキュリティ要件を明記
5. **パフォーマンス考慮不足**: パフォーマンス要件を明記
