# テスト駆動開発タスク定義

## Phase 1: テスト環境構築
もしtokenがなくなった場合はそのタイミングで終了すること

### タスク 1.1: テストフレームワーク設定
**優先度**: 高
**推定時間**: 2時間

#### 要件
- Jest + React Testing Libraryの導入
- MSW（Mock Service Worker）の設定
- カバレッジ設定（80%以上）
- テスト用ユーティリティ関数の作成

#### テスト要件
- テスト環境が正常に動作することを確認
- モックサーバーがAPIリクエストを適切に処理
- カバレッジレポートが生成される

#### 技術的制約
- Next.js 15.1.8との互換性
- Supabase認証のモック化
- TypeScript対応（将来的な移行を考慮）

#### 期待結果
- `npm test`でテストが実行できる
- カバレッジレポートが生成される
- CI/CDパイプラインでテストが実行できる

---

**優先度**: 高
**推定時間**: 1時間

- 優先度・タグの検証関数
- エラーメッセージの統一

#### テスト要件
- 正常なデータの検証
- 各フィールドの必須チェック
- 文字数制限の検証
- 不正な値の検証

#### 技術的制約
- 既存のフォームバリデーションロジックとの整合性
- 国際化対応（将来的）

#### 期待結果
- バリデーション関数が100%テストカバー
- エラーメッセージが適切に表示される

## Phase 3: APIテスト

### タスク 3.1: APIエンドポイントの統合テスト
**優先度**: 高
**推定時間**: 3時間

#### 要件
- 各APIエンドポイントの動作確認
- 認証・認可の確認
- エラーハンドリングの確認
- レスポンス形式の確認

#### テスト要件
- GET /api/issues - 課題一覧取得
- POST /api/register - 課題作成
- PUT /api/update - 課題更新
- PUT /api/status - ステータス更新
- 認証エラーの処理
- バリデーションエラーの処理

#### 技術的制約
- Supabase RLSポリシーとの整合性
- 既存のデータベーススキーマとの整合性

#### 期待結果
- 全APIエンドポイントが正常に動作する
- セキュリティが適切に機能する

## 実装順序

1. **Phase 1**: テスト環境構築（基盤）
2. **Phase 2**: コンポーネントテスト（UI層）
3. **Phase 3**: APIテスト（バックエンド層）
4. **Phase 4**: E2Eテスト（統合）
